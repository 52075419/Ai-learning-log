## 一、AI 的层次关系

### 1.1 四层包含关系
人工智能 (AI)
└── 机器学习 (ML)
└── 深度学习 (DL)
├── 大语言模型 (LLM)
├── 图像生成模型
├── 视频生成模型
├── 图像识别模型
└── 语音模型

**记忆口诀**：AI 最大，机器学习是其中一种方法，深度学习是机器学习里用神经网络的那种，大语言模型 / 图像视频生成是深度学习的"孩子"。

### 1.2 每一层的准确含义

| 层次 | 定义 | 关键判断 |
|------|------|---------|
| AI | 让机器表现出智能行为的技术总称，是最大的"筐" | 不一定要"学习"，人写死规则也算 AI |
| 机器学习 | 让计算机从数据中学习规律的方法 | 核心是"从数据中学习" |
| 深度学习 | 机器学习的一种，用多层神经网络来学习 | 必须是"神经网络 + 多层" |
| 大语言模型 | 通常使用深度神经网络，从大规模数据中学习语言及相关任务的模型 | 专攻"语言"，基于 Transformer |

### 1.3 三个最容易搞混的点

- ❌ "AI 就是机器学习" → AI 更大，机器学习只是其中一种方法；传统专家系统靠人工规则推理，也属于 AI
- ❌ "机器学习就是深度学习" → 深度学习只是机器学习里用神经网络的那种
- ❌ "大模型 = AI" → 大模型只是 AI 里一个很小的分支
- ❌ "生成式 AI 都是大语言模型" → 图像生成模型可采用扩散模型、Transformer 或两者结合

### 1.4 用"会不会自己学"来区分

- AI：不一定自己学，可以人写规则
- 机器学习：一定会自己从数据里学
- 深度学习：用神经网络自己学
- 大模型：用超大神经网络，从海量数据里学语言及相关任务

每往下一层，"自己学"的程度更高、方法更具体。

## 二、机器学习原理

### 2.1 三要素

1. 数据（很多例子）
2. 模型（一个会算的公式）
3. 训练（不断调整公式，让它猜得越来越准）

### 2.2 通俗比喻

就像教小孩认猫：不告诉他规则，而是给他看 1000 张猫的图片，他自己总结出"长这样的就是猫"。

### 2.3 机器学习不都需要大量人工标注

上面的比喻容易让人以为"机器学习一定需要人工标注"，其实不是。机器学习分几类：

| 学习方式 | 基本原理 | 例子 |
|---------|---------|------|
| 监督学习 | 使用带目标答案的数据学习 | 根据历史房价预测房价 |
| 无监督学习 | 从数据中寻找结构或规律 | 将客户划分为不同群体 |
| 自监督学习 | 从数据本身构造训练目标 | 根据上下文预测下一个 Token |
| 强化学习 | 根据行动及奖励调整策略 | 训练智能体完成特定任务 |

**初学者最值得先理解的是监督学习和自监督学习。**

大语言模型预训练时，可以从一段文本中构造"预测后续 Token"的任务，不需要人为标注每个位置的标准答案，这就是自监督学习。后续的监督微调则使用包含问题和理想回答的数据。两者训练目标不完全相同。

## 三、大语言模型的本质

### 3.1 核心原理

**通俗理解：它是"超级词语接龙机器"**——给它一段话，它预测"下一个最可能出现的 Token"，一个 Token 一个 Token 往外蹦，形成回答。

例：输入"今天天气真"，它预测下一个 Token 可能是"好"，输出"今天天气真好"。

**但底层单位不是"完整的词"，而是 Token。** 一个 Token 可能对应：一个汉字、一个英文单词、英文单词的一部分、标点符号或其他文本片段，具体取决于模型使用的分词器。

### 3.2 需要补充的三个认知

1. **预测下一个 Token 是重要的训练目标，但不意味着模型只会"接龙"。** 通过大规模训练，模型可能学会语言结构、知识关联、代码模式以及解决问题所需的中间步骤。
2. **模型不等于传统数据库。** 模型主要通过训练得到的参数计算输出，而不是简单搜索数据库并拼接答案。当然，模型也可能记住部分训练数据。
3. **不是所有模型都只做逐 Token 文本生成。** 多模态模型可能处理文本、图像、音频等信息，一些模型还会调用工具或执行额外的推理计算。

**更准确的表述**：大语言模型通常通过预测后续 Token 等训练目标，从大规模数据中学习语言及相关任务的规律。生成回答时，模型根据上下文计算后续 Token 的概率，并逐步产生输出。预测 Token 是其重要的工作机制，但不能完全代表模型的全部能力。

### 3.3 为什么厉害

- 训练数据极其庞大（几乎整个互联网的文本）
- 模型参数极多（几千亿个"旋钮"）
- 所以能"记住"大量知识，并模仿人类表达

### 3.4 重要认知

DeepSeek 不是"会思考的人"，是强大的语言预测工具。它能帮你写代码、查资料、理思路，但也会犯错（幻觉），你需要有判断力。

## 四、大模型为什么这几年爆发

### 4.1 一句话答案

不是"突然变聪明"，而是三个条件同时成熟了：数据够了、算力够了、算法对了。

### 4.2 三个条件

| 条件 | 比喻 | 说明 |
|------|------|------|
| 数据 | 食材 | 互联网文本被数字化、可抓取，训练动辄几十万亿 Token |
| 算力 | 灶火 | GPU 特别适合神经网络计算，云计算让普通公司也能租到成千上万张 GPU |
| 算法 | 菜谱 | 最关键的突破，见下面四个里程碑 |

### 4.3 算法上的四个关键突破

1. **2017 年 Transformer 架构（最关键的转折点）**
   - Google 论文《Attention Is All You Need》
   - 注意力机制让模型同时关注句子里所有词的关系
   - 特别适合并行计算，能充分利用 GPU
   - DeepSeek、GPT、文心一言全都基于 Transformer

2. **2018–2020 年 预训练 + 微调范式**
   - 预训练：先用海量无标注文本让模型"泛读"，学会语言一般规律
   - 微调：再用少量标注数据，教它做具体任务
   - 效果：一次学习，处处可用

3. **2020 年后 Scaling Law（规模定律）**
   - 模型越大、数据越多、算力越强，效果越好，而且可以预测
   - 给了所有人信心：只要堆资源，就能变强

4. **2022 年后 RLHF（人类反馈强化学习）**
   - 让人类给模型回答打分，模型根据反馈调整
   - 学会"说人话、说得有用、说得安全"
   - ChatGPT 爆火的重要推手之一，让模型从"能用"变"好用"

### 4.4 时间线

| 年份 | 事件 |
|------|------|
| 2012 | 深度学习在图像识别上大突破（AlexNet） |
| 2017 | Transformer 诞生（算法突破） |
| 2018 | GPT-1、BERT 出现，预训练范式确立 |
| 2020 | GPT-3 发布，1750 亿参数 |
| 2022 | ChatGPT 发布，RLHF 让它好用，全球爆火 |
| 2022 | Stable Diffusion 开源（图片生成爆发） |
| 2023 | GPT-4、开源模型爆发，中国大模型跟进 |
| 2024 | Sora 发布（视频生成爆发） |
| 2024–2025 | DeepSeek 等高效模型出现，成本大降 |

### 4.5 三个条件缺一不可

- 只有算法，没数据和算力 → 训练不出来（2017 年前）
- 只有数据和算力，没好算法 → 训出来也是废物（2000 年代）
- 三者齐备 → 指数级爆发（2020 年后）

### 4.6 助推器：成本 + 开源 + API

- 成本下降：DeepSeek 这类模型用更少算力达到接近顶级效果
- 开源：模型权重公开，全世界开发者都能改、能用
- API 化：不用自己训模型，调用接口就能用

## 五、神经网络要学到什么程度

### 5.1 结论

| 目标 | 要不要深学神经网络 |
|------|------------------|
| 用 AI 辅助做软件开发 | ❌ 不需要深学，懂概念即可 |
| 研究 AI、训练模型、做算法岗 | ✅ 必须深学 |

**比喻**：你要开车，需要懂发动机燃烧原理吗？不需要。你只需要知道踩油门加速、踩刹车停、方向盘控制方向。神经网络就是"发动机"，你是"驾驶员"。

### 5.2 只需懂的 5 个概念

1. **神经元**：一个"小计算单元"，接收输入，加权求和，输出结果
2. **层（Layer）**：很多神经元排成一层，多层叠起来就是"深度"神经网络
3. **权重（Weight）**：每个连接的"重要程度"，训练就是不断调整这些权重
4. **训练**：给模型看数据 → 它猜 → 猜错了 → 调整权重 → 再猜……反复几百万次
5. **推理（Inference）**：训练好之后，输入内容，它给出结果（调用 DeepSeek API 用的就是推理）

### 5.3 为什么现在深学神经网络公式"性价比低"

1. 学三个月数学，可能还不如 DeepSeek 一秒生成的代码有用
2. 真正的算法研究需要硕博级数学功底，投入产出比不划算
3. 你的核心竞争力是"用 AI 造东西"，不是"造 AI"

### 5.4 什么时候才需要深学

如果以后想自己训练/微调模型、做算法工程师、研究模型架构，那时候再补数学（线性代数、微积分、概率论）也不迟。但对"独立做软件开发"这个目标，永远不需要。

## 六、图片/视频生成属于哪类

### 6.1 结论

属于深度学习，和大语言模型是"兄弟关系"，不是父子关系。
深度学习 (DL)
├── 大语言模型 (LLM) ← 处理文字
├── 图像生成模型 ← 处理图片（Stable Diffusion、Midjourney、DALL·E）
├── 视频生成模型 ← 处理视频（Sora、可灵、Runway）
├── 图像识别模型 ← 看懂图片
├── 语音识别模型 ← 声音→文字（Whisper）
└── 语音合成模型 ← 文字→声音（TTS）


### 6.2 按"处理什么"分类

| 类型 | 输入→输出 | 代表模型 |
|------|----------|---------|
| 大语言模型 | 文字→文字 | DeepSeek、GPT |
| 图像生成 | 文字→图片 | Midjourney、Stable Diffusion |
| 视频生成 | 文字/图片→视频 | Sora、可灵 |
| 图像识别 | 图片→文字/标签 | 人脸识别、医学影像 |
| 语音识别 | 声音→文字 | Whisper |
| 语音合成 | 文字→声音 | TTS 模型 |

### 6.3 图片/视频生成用的具体技术

**① 扩散模型（Diffusion）—— 目前主流**

- 代表：Stable Diffusion、Midjourney、Sora
- 原理：训练时给图片不断加噪声直到变乱码，让模型学"怎么从噪声还原图片"；生成时给一团随机噪声，让它一步步"去噪"，逐渐变出一张图
- 比喻："从一团雪花屏里，慢慢雕琢出一幅画"

**② GAN（生成对抗网络）—— 早期主流**

- 代表：早期换脸、生成人脸
- 原理：两个网络互相对抗，一个"造假"（生成器），一个"鉴假"（判别器），越斗越强
- 比喻："造假者和鉴定师互相较量，水平都越来越高"

**注意**：生成式模型不止这两类，还有自回归生成模型、基于 Transformer 的生成模型、不同技术组合形成的混合架构。Transformer 与扩散模型也不是相互排斥的，它们可以在同一个生成系统中发挥不同作用。不必在第 0 阶段深入研究其内部架构。

### 6.4 通用判断法

**问题 1：它是不是从数据里自己学？**

- 是 → 机器学习
- 用神经网络学 → 深度学习

**问题 2：它处理什么？**

- 文字 → 大语言模型
- 图片 → 图像模型（生成 or 识别）
- 声音 → 语音模型
- 视频 → 视频模型

## 七、为什么 LLM 爆发带动了图片/视频爆发

### 7.1 结论

不是"没有因果关系"，也不是"简单因果"。真相是：**同源 + 带动 + 共生**。

> 大语言模型、图片生成、视频生成，是同一场"深度学习革命"的三个孩子。它们共享同一个"爹"（底层技术突破），又互相"喂饭"（彼此借鉴）。

### 7.2 驱动力一：共同的底层技术底座（主因）

| 共享的底层技术 | 对大语言模型 | 对图片/视频生成 |
|--------------|-------------|----------------|
| Transformer 架构（2017） | 直接用它 | 后来也大量融合它（如 Sora） |
| GPU 算力 | 需要海量显卡 | 同样需要 |
| 大规模数据 + 训练方法 | 用海量文本 | 用海量图文对 |
| Scaling Law | 越大越强 | 同样越大越强 |
| 开源 + 云 + 资本投入 | 受益 | 同样受益 |

**比喻**：就像"电力革命"同时点亮了电灯、电话、电车——不是电灯导致了电话，而是电力这个底座成熟了，所有用电的东西一起爆发。Transformer、GPU、Scaling Law 就是 AI 时代的"电力"。

### 7.3 驱动力二：LLM 确实"带动"了图片/视频（真实因果）

1. **资本和人才涌入**：ChatGPT 爆火 → 全世界看到 AI 能赚钱 → 大量资金、人才涌入整个 AI 领域
2. **技术外溢**：LLM 证明了 Transformer + 大规模训练有效，图片生成团队直接借用（如 Sora 用 Transformer 做视频）
3. **基础设施成熟**：为训 LLM 建的 GPU 集群、训练框架，图片/视频生成可直接复用，成本大降
4. **需求被唤醒**：ChatGPT 让大众接受了"AI 能创作"，用户开始期待"AI 也能画图、做视频"

### 7.4 驱动力三：它们互相"喂饭"（双向促进）

- LLM → 图片/视频：提供 Transformer 经验、算力基建、资本、用户认知
- 图片/视频 → LLM：推动多模态发展（让 LLM 能"看图说话"），反过来增强 LLM

### 7.5 用时间线看"谁先爆发"

| 时间 | 事件 |
|------|------|
| 2017 | Transformer 诞生（共同底座） |
| 2020 | GPT-3 爆火（LLM 先冲） |
| 2022 | ChatGPT 引爆全球（LLM 巅峰）→ 资本、人才疯狂涌入 |
| 2022 | Stable Diffusion 开源（图片生成爆发） |
| 2023 | Midjourney 出圈，图片生成大众化 |
| 2024 | Sora 发布（视频生成爆发） |

看顺序：LLM 先爆发（2022）→ 带动资本和基建 → 图片/视频紧随其后（2022–2024）。这个先后顺序本身就说明有带动关系，不是纯同步。

### 7.6 最终准确表述

> 图片/视频生成的爆发，是"共同底层技术成熟"（主因）+ "大语言模型带动"（助推）+ "彼此互相促进"（生态）三者共同作用的结果。说"完全没因果"不对，说"LLM 直接导致"也不对。准确说是：同源 + 带动 + 共生。

## 八、Scaling Law（规模定律）

### 8.1 一句话定义

模型越大、数据越多、算力越强，效果就越好——而且这种"变好"是可以预测的。

### 8.2 三个关键变量

| 变量 | 通俗解释 | 例子 |
|------|---------|------|
| 模型规模 (N) | 模型有多少参数（多少"旋钮"） | GPT-3 有 1750 亿参数 |
| 数据规模 (D) | 用了多少文本训练 | 几万亿个 Token |
| 算力 (C) | 训练花了多少计算 | 几千张 GPU 跑几个月 |

**核心发现**：这三个一起增加，效果（用"损失"衡量）会按幂律下降。

### 8.3 什么是"幂律下降"

- 普通增长：投入翻倍，效果提升一点点
- 幂律：投入翻倍，效果稳定地提升一个固定比例
- 特征：平滑曲线，不是突然跳变；可以画图、拟合、外推预测

**比喻**：像你知道"每多跑 1 公里，大概多消耗 60 卡路里"——不是绝对精确，但大方向可预测。

### 8.4 效果曲线
效果（越好越高）
│
│●●
│ ●●
│ ●●●
│ ●●●●●
│ ●●●●●●●●●
└────────────────────────→ 资源（模型+数据+算力）

一直上升，但上升速度逐渐放缓（收益递减）——想再提升一点，需要投入更多。

### 8.5 不能简单理解为"模型越大就越聪明"

模型效果不仅受参数规模影响，还与以下因素有关：

- 训练数据的质量
- 数据的数量和分布
- 训练计算量
- 模型架构
- 训练方法
- 后训练过程
- 推理时使用的计算资源

如果只是增加参数，却没有合理配置训练数据和计算资源，模型效果未必达到预期。

**更准确地说**：Scaling Law 描述的是——在特定训练条件和评估指标下，模型性能与模型规模、数据规模、计算量等因素之间存在可预测的经验关系。

此外，模型的某些能力看似突然出现，也可能与评估指标、测试方式及模型规模变化有关，不宜把所有能力提升都解释为"跨过某个明确临界点"。

### 8.6 为什么重要

1. **给了行业信心**：在 Scaling Law 之前，大家不知道堆资源有没有用；有了它，知道只要堆就会变强，而且能预测 → 于是疯狂投入
2. **指导资源分配**：不只"堆得多"，还要"堆得对"——模型太大但数据太少→浪费；数据太多但模型太小→浪费；三者要平衡
3. **解释了"为什么大模型突然行"**：不是算法突然变神，而是规模跨过某个门槛，能力"涌现"出来了

### 8.7 涌现（Emergence）

当规模大到一定程度，模型会突然学会一些之前完全不会的能力。

- 规模小时：不会做数学题
- 规模大到某点：突然会了
- 再大：还会推理、写代码……

**比喻**：类似"水加热到 100°C 突然沸腾"——之前只是变热，到点就质变。

**注意**：涌现也可能与评估方式有关，不宜过度绝对化。

### 8.8 局限性

- **数据快用完了**：互联网高质量文本有限，不能无限堆
- **收益递减**：越往后，投入越大、提升越小
- **成本爆炸**：堆规模的代价越来越高

所以现在大家转向：更聪明地用小资源（如 DeepSeek 的高效训练）、优化算法和数据质量，而不只是堆量。DeepSeek 的一大贡献，就是证明了"不一定要堆到极致，也能达到顶级效果"。

### 8.9 做菜的比喻

> Scaling Law 就像"做菜的配方规律"：食材越多、火候越足、时间越长，菜越好吃；而且大概能预测多加一倍食材好吃程度提升多少；但不是无限的——食材加到一定程度，再加也没用，甚至难吃；所以关键不只是"多"，还要"配比合理"。

## 九、算法 vs 模型

### 9.1 一句话区分

> 算法是"方法/过程"，模型是"结果/产物"。
> 算法是"怎么学"，模型是"学完之后那个会干活的东西"。

### 9.2 做菜的比喻

| 概念 | 对应 | 说明 |
|------|------|------|
| 算法 | 菜谱 + 烹饪方法 | "先炒后炖，火候多少"——一套做法 |
| 模型 | 做好的那盘菜 | 按菜谱做出来的成品 |

- 菜谱（算法）是过程、方法
- 菜（模型）是结果、产物
- 同一个菜谱可做很多盘菜（同一算法可训练出多个模型）

### 9.3 回到 AI 的具体区分

**算法（Algorithm）= 学习的方法**，例如：

- 反向传播 + 梯度下降：怎么调整权重的方法
- 扩散（Diffusion）：一种"加噪-去噪"的生成方法
- RLHF：一类利用人类反馈改进模型行为的训练方法

**模型（Model）= 学完之后的产物**，例如：

- DeepSeek-V3：一个训练好的模型（一堆参数文件）
- GPT-4：一个训练好的模型
- Stable Diffusion：一个训练好的图片生成模型

### 9.4 用一次完整流程看关系
选架构 → 决定用 Transformer（结构怎么搭）

准备数据 → 海量文本

训练 → 用训练算法反复调整参数（过程）

得到模型 → 训练结束，产出一个"模型"（结果）

推理 → 用模型干活（调用 API 时用的就是它）

### 9.5 更严谨的五层区分

| 概念 | 具体含义 | 例子 |
|------|---------|------|
| 架构 | 模型的计算结构如何设计 | Transformer |
| 训练算法 | 如何根据训练目标更新参数 | SGD、AdamW |
| 学习目标 | 模型通过训练需要优化什么 | 预测下一个 Token |
| 训练方法 | 如何组织训练过程 | 预训练、监督微调 |
| 模型 | 训练后得到的具体模型 | DeepSeek-V3 等 |

**注意**：这张表是为了帮助初学者理解概念，实际工程中这些概念的边界并不总是如此简单。你现阶段只需记住：**Transformer 是架构，不是训练算法；训练算法是梯度下降/AdamW 这类；模型是训练后的产物。**

### 9.6 关于"Transformer 突破"的定位

- Transformer = 一种**神经网络架构**（规定模型如何组织计算模块、如何通过注意力机制处理序列信息）→ 属于架构层
- DeepSeek、GPT = 用 Transformer 架构训练出来的模型 → 属于产物层
- ✅ "Transformer 是架构"：对
- ❌ "DeepSeek 是算法"：不准确（它是模型，是产物）
- ✅ "DeepSeek 用了 Transformer 架构"：完全正确

### 9.7 参数量的归属

参数量主要取决于架构（网络搭多大、多深、多宽），而不是训练算法。训练算法只负责调整这些参数的值，不决定参数个数。

- 架构 = 造一台机器，上面装多少个"旋钮"——设计时定死
- 训练算法 = 用什么方法去拧这些旋钮
- 参数量 = 旋钮的总个数，造好就固定了

### 9.8 训练算法怎么确定"旋钮扭到哪"

核心流程：前向传播（猜）→ 算损失（错多少）→ 反向传播（算每个旋钮的责任/梯度）→ 梯度下降（扭旋钮）→ 重复几百万次。

只需记住的 5 个概念：

| 概念 | 一句话 |
|------|--------|
| 梯度 | 告诉你每个旋钮往哪边扭能让错误变小 |
| 梯度下降 | 跟着梯度方向，每次扭一点点，反复几百万次 |
| 反向传播 | 从错误倒着往回算，算出每个旋钮的梯度 |
| 学习率 | 每次扭多大一步（太大跨过谷底，太小学得慢） |
| 损失 | 模型猜的答案和正确答案差多少（错误程度） |

**不需要深学**：梯度公式、反向传播推导、损失函数具体形式、优化器内部机制。这些是算法工程师/研究者才需要的，对你的目标（用 AI 做开发）不必要。

### 9.9 一句话总结三者关系

> 架构是"造成什么形状"的设计，训练算法是"怎么调参数"的方法，模型是"造出来的成品"。
> 架构 + 数据 + 训练算法 →（训练）→ 模型

## 十、学习心态与路线

### 10.1 三个重要心态

1. **AI 会犯错，你要有判断力**：DeepSeek 再强也会一本正经胡说八道（幻觉），它给的代码可能有 bug、说的"事实"可能编的。你的角色不是"照抄"，而是"审核 + 判断"。
2. **AI 是"副驾驶"，不是"自动驾驶"**：错误心态是"我什么都不用懂，让 AI 写就行"；正确心态是"我懂原理和方向，让 AI 帮我加速执行"。你越懂，AI 对你越有用。
3. **别追求"学完再动手"**：AI 领域永远学不完，正确姿势是边学边做，做中学。

### 10.2 AI 对程序员的影响（不过度预测）

不宜简单断言"哪类程序员一定会被取代"。AI 对工作的影响，往往会先改变具体任务，再逐渐影响岗位结构。

软件开发不仅包括代码编写，还涉及：需求分析、系统设计、安全审查、测试与调试、系统维护、与真实业务环境的集成。这些工作也会受 AI 影响，只是程度和速度不同。

**更值得关注的是**：如何借助 AI 完成实际任务，并具备验证结果、发现问题、解决异常的能力。

### 10.3 学习节奏建议

| 建议 | 说明 |
|------|------|
| 每天少量、持续 | 每天 30–60 分钟，比周末突击 5 小时有效 |
| 动手 > 看书 | 看懂 ≠ 会做，一定要自己敲代码、跑程序 |
| 允许自己忘 | 忘了正常，重要的是知道"有这么个东西"，需要时能查回来 |
| 记录问题 | 遇到不懂的记下来，问 AI 或问导师，别跳过 |

### 10.4 后面会遇到的两个坑

1. **环境配置劝退**：装 Python、配环境、命令行报错……90% 初学者的第一道坎。别怕，第 2 阶段会专门解决。
2. **看得懂但写不出**：看别人代码觉得"懂了"，自己一写就懵。正常，唯一解法是多写、多错、多改。

### 10.5 该不该深入学习的判断框架（四问法）

以后遇到任何知识点，问自己：

| 问题 | 如果"是" | 如果"否" |
|------|---------|---------|
| 1. 它会影响我"用 AI 做开发"吗？ | 学概念 | 跳过 |
| 2. 它是"造 AI"的知识还是"用 AI"的知识？ | 造 AI → 跳过 | 用 AI → 学概念 |
| 3. 我现在不学，以后用到时补来得及吗？ | 来得及 → 先跳过 | 来不及 → 现在学 |
| 4. 我学它，是为了"理解"还是为了"安心"？ | 安心 → 跳过 | 理解 → 学概念 |

### 10.6 提问策略

值得多问的（帮你建立框架）：

- "这个概念和我之前学的 XX 是什么关系？"
- "这个知识我现在需要学吗？还是以后再说？"
- "为什么是这样？背后的逻辑是什么？"
- "我理解得对不对？"

**核心认知**："知道有这么个东西 + 知道去哪查" > "现在背熟所有细节"。学习是螺旋上升，不是一次学完。

### 10.7 学习 AI 的五条路线（明确你走哪条）

"学习 AI"实际包含几条差别很大的路线：

| 路线 | 重点 | 适合谁 |
|------|------|--------|
| A. AI 工具使用与效率提升 | 提问技巧、多模型使用、文档处理、判断回答可靠性 | 想提升日常效率，不一定学编程 |
| B. AI 应用开发 | Python、API 调用、JSON、Prompt、RAG、工具调用、工作流、智能体、数据库与部署、测试评估 | 想用现有模型开发解决实际问题的软件 |
| C. AI 算法与技术原理 | 线代、概率、微积分、机器学习、深度学习、PyTorch、Transformer 内部、模型微调 | 想研究模型内部原理或做算法岗 |
| D. AI 与现有专业结合 | 专业文档分析、数据处理、业务流程自动化、专业知识问答、报告生成 | 想把 AI 用到自己的专业领域 |

**你的目标对应路线 B（AI 应用开发）**：不一定自己训练模型，而是利用现有模型，开发能解决实际问题的软件。

**路线 B 的核心能力链**：AI 基础认知 → Python 基础 → API 调用 → AI 应用开发 → RAG → 工作流与智能体 → 项目实战。

**注意**：不必从路线 C（算法原理）开始。路线 C 是"造 AI"，路线 B 是"用 AI 造东西"。

### 10.8 六阶段路线图（对应路线 B）

| 阶段 | 主题 | 目标 |
|------|------|------|
| 第 0 阶段 | AI 基础认知 | 搞懂 AI、机器学习、深度学习、大模型 |
| 第 1 阶段 | 编程基础（Python） | 能读懂并写出简单 Python 程序 |
| 第 2 阶段 | 开发环境与工具 | 会用编辑器、命令行、Git、API |
| 第 3 阶段 | 与大模型协作 | 掌握 Prompt 工程，会用 DeepSeek API |
| 第 4 阶段 | 软件工程基础 | 理解需求、架构、调试、测试 |
| 第 5 阶段 | 独立开发实战 | 在 DeepSeek 辅助下完成一个完整项目 |

学完 6 阶段能做到：看懂 Python 代码、会用 DeepSeek API、能把想法拆成可执行任务、在 DeepSeek 辅助下独立完成一个能用的软件。不是成为算法专家，而是成为"能用 AI 造东西的人"。
